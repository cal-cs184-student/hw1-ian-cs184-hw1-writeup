Overview

This homework builds a simplified SVG rasterizer. I began with single-color triangles, then added subpixel coverage, hierarchical transforms, smoothly varying vertex colors, texture lookup, and mipmap selection.

The throughline is sampling. Geometry decides where a pixel is covered; barycentric coordinates tell me what to interpolate there; texture filtering decides which detail the pixel can display. The clearest lesson for me was that a smooth triangle edge does not guarantee a smooth texture: supersampling, pixel filtering, and mipmaps address different visible problems.

01

Single-Color Triangles

Triangle coverage starts with three directed edges and a sample at each pixel center.

The approach

I compute the smallest axis-aligned bounding box around the triangle, clip it to the framebuffer, and visit only pixel centers within it. For each center at (x + 0.5, y + 0.5), three edge functions test which side of each directed edge it lies on. I normalize the signs to handle clockwise and counterclockwise vertex order, and use inclusive edge comparisons before filling the pixel.

EDGE TESTE(A, B, P) = (Bₓ − Aₓ)(Pᵧ − Aᵧ) − (Bᵧ − Aᵧ)(Pₓ − Aₓ)

For a bounding box W pixels wide and H pixels tall, I test at most W × H sample positions, so the worst-case work is O(W × H). That is no worse than checking every sample in the bounding box, and a small triangle never triggers a scan of the whole framebuffer. Handling both winding orders and samples on edges were the main coverage cases to get right.

Extra credit: faster edge evaluation

I rewrote each edge function as Ax + By + C and calculated its coefficients once. Moving right by one pixel adds A to the edge value; moving down one row adds B. A triangle intersects a scanline in one interval, so the scan can stop after leaving a covered run. I timed svg.draw() in DrawRend::redraw() on basic/test4.svg under the same viewing conditions. The optimized version reduced mean draw time by 23.2% across five measurements.

02

Supersampling

Subpixel coverage turns a binary edge decision into an estimate of how much of a pixel is covered.

Buffer and resolve

At sample rate N, each pixel owns a regular √N × √N grid of sample colors. I store those N colors contiguously in a width × height × N sample buffer. Triangle rasterization tests each subpixel center and writes only covered samples. Points and lines fill all samples of an output pixel, since those primitives are not supersampled here. After drawing, resolve_to_framebuffer() averages a pixel's samples into one RGB value.

SUBPIXEL CENTERxₛ = x + (sₓ + 0.5)/√N   ·   yₛ = y + (sᵧ + 0.5)/√N

The buffer must resize when the viewport or sample rate changes. A single center sample can miss a skinny corner entirely. Four samples permit quarter steps in coverage; sixteen permit sixteenth steps. Averaging covered and uncovered samples softens edges, at roughly proportional cost in storage and coverage tests. The three captures below keep the default view and pixel-inspector position fixed.

The pixel inspector makes the change visible along the thin red triangle. With one sample, each pixel is either fully red or background. With four samples, one, two, or three covered subpixels can resolve to roughly 25%, 50%, or 75% red coverage. Sixteen samples allow still finer steps, so the narrow edge fades more gradually instead of disappearing between pixel centers.

Transforms

A running Cubeman makes transform order and nesting visible.

For my_robot.svg, I designed a runner moving to the right: a forward-leaning torso and head, one raised knee, one extended leg, and arms swinging. Different body colors distinguish the moving components.

Each limb begins with a shoulder or hip translation, then a rotation of the upper limb. Translating to the elbow or knee creates a child frame, where a second rotation bends the lower limb. This hierarchy lets a shoulder carry its forearm along without manually changing every polygon coordinate. The rendered screenshot shows the pose.

04

Barycentric Coordinates

Barycentric coordinates turn vertex attributes into values at any point inside a triangle.

A point inside a triangle is a weighted combination of its vertices. The weights α, β, γ sum to one. At a vertex, its own weight is one; near the center, all three vertices contribute. I use the same weights to interpolate RGB vertex colors and, later, UV texture coordinates.

INTERPOLATIONP = αV₀ + βV₁ + γV₂   ·   C(P) = αC₀ + βC₁ + γC₂

The custom red/green/blue triangle shows a smooth three-way blend. The basic/test7.svg color wheel extends the same interpolation across adjoining triangles; compatible shared vertex colors make its gradient appear continuous.

05

Pixel Sampling

Texture filtering changes the appearance inside triangles; supersampling changes their edges.

For each covered sample, I interpolate the triangle's vertex UV coordinates with its barycentric weights: u = αu₀ + βu₁ + γu₂, with the same calculation for v. I convert that normalized UV location to texture coordinates and write the sampled color into the sample buffer. Nearest sampling rounds to the closest texel and reads one color. Bilinear sampling reads the four surrounding texels, blends each horizontal pair, then blends those two results vertically using the sample's fractional position.

I used the same globe from the svg/texmap/ examples and held the pixel inspector over its thin map grid for all four captures. This lets the two texture filters be compared at each sample rate while the view stays fixed.

In the inspector, nearest filtering switches abruptly between blue ocean and pale grid-line texels; bilinear filtering blends those neighbors into a more gradual transition. Comparing 1 and 16 samples per pixel within either filtering method, the globe's curved boundary also becomes smoother, while each subpixel still uses the selected texture filter. The difference between nearest and bilinear is greatest when magnified neighboring texels have strongly different colors, such as grid lines and coastlines. Uniform blue areas change little because there is almost no color difference to blend.

06

Level Sampling

Mipmaps address too many texture details competing for too few screen pixels.

A mipmap stores the original texture at level zero and progressively smaller, prefiltered copies at higher levels. When many original texels collapse into one screen pixel, choosing a smaller copy filters out detail that the screen cannot represent. For each sample, I interpolate UV coordinates at its position and one pixel away in both x and y. I scale the UV differences by the original texture's width and height, take the larger texel-space footprint ρ, and use log₂(ρ) to estimate the level. L_ZERO always uses level zero; L_NEAREST rounds to the closest available level. L_LINEAR blends the two surrounding levels and becomes trilinear filtering when paired with bilinear pixel sampling.

LEVEL OF DETAILL = log₂(max(‖ΔUVₓ‖, ‖ΔUVᵧ‖))   in level-zero texels

I chose a UC Berkeley symbol PNG for this comparison: its seal has large shapes alongside fine lettering, dots, and thin lines. The captures use the same view and inspector region. At level zero, fine details appear sharper but noisier; selecting a prefiltered mipmap level softens the seal and lettering when they occupy fewer screen pixels. Bilinear sampling blends only four texels within one level, so it cannot by itself remove all of that minification aliasing.
